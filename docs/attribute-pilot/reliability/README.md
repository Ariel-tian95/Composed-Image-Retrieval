## 你现在先做什么

开发集50张已经标完。下一步将`human-labels/labels_dev_B.csv`上传Kaggle，运行开发集预测与评价。以下规则保留供复查及后续评估集标注使用。

1. 填你的姓名或代号，点击“开始/恢复本人的标注”。只看到开发集50张，没有模型预测。
2. 每张填主颜色、袖长、主图案。只标当前主要衣服，不根据dress/shirt/toptee子集名推断真值；多件难分主次用uncertain并备注。原图按钮可查看PNG，勿只靠缩略图猜细节。
3. 主颜色用主体服装的可见主色；无明显主色选multicolor。颜色不推断材质或被遮挡部分。
4. 袖长：sleeveless无袖，short肘上，elbow肘附近，three_quarter肘与腕之间，long腕附近；遮住袖子不能直接选无袖。
5. 主图案：plain素色、stripe条纹、check格纹、dot圆点、floral花卉、letters_graphics文字/图形、mixed无法定主次的混合。本轮letters_graphics是合并类，不冒充Fashionpedia细分文字标签。小logo不主导衣服时暂记plain并备注；这是开发规则，要在评估前冻结。
6. unknown表示可见但词表不涵盖；uncertain表示可见但有争议；not_visible表示未呈现/遮挡；空白表示还没标。三种不确定状态不计为普通负标签，建议注明原因。
7. 点击导出，文件名形如labels_dev_B.csv，通常在浏览器下载目录。可中途导出；下次先填同一代号，再导入该CSV续标。浏览器缓存不替代导出文件，原CSV务必保留。
8. 评估集100张由另一成员独立打开eval_人工标注.html盲标为佳，不看模型预测，也不先看别人的答案。若只有同一成员标，报告需如实记录。

不同标注者各自保存CSV。脚本遇到同图不同标签/不同标注者不会自动覆盖，会生成conflicts.json并停止。团队逐项裁决，保留两份原CSV与裁决记录后，再提供一份明确的最终真值CSV。

## Kaggle按顺序做什么

导入 `notebooks/attribute_reliability.ipynb`（本机交付目录也有同名文件）。旧attribute_pilot.ipynb已更新为引导入口，使用本新本。

1. 开启Internet，GPU选择T4。右侧Upload添加本机 `attribute_pilot_150_png.zip`，约14MB，只含固定150张原始PNG。无需上传整套FashionIQ。
2. 运行“代码与依赖”和“恢复原图和官方权重”。优先复用team-baseline原权重/代码；没有时会下载官方2.53GB权重并固定官方commit。150张图片逐张验哈希。
3. **先完成开发集盲标，再看预测。** 运行开发集预测50张，得到dev_predictions.json。模型只是官方权重中的冻结CLIP，不用IVS/VTE，不重新训练。
4. 把你导出的labels_dev_代号.csv通过Upload挂载，再运行载入CSV与开发评价。无标签时只写pending状态，准确率/F1不虚构。
5. 根据开发集分析混淆与错误；如要改提示词，只能这时改。改过代码必须重新跑开发集。确认后把FREEZE_PROTOCOL改True、FREEZE_REVIEWER填实际代号，再运行冻结单元格，下载保存protocol_lock.json。
6. 挂载独立完成的labels_eval_代号.csv，重新运行CSV合并单元格。发生分歧先裁决。确认100行均已标注后，将RUN_EVAL改True，运行评估100张。必须使用同一方案锁和脚本版本，禁止看评估结果再调参。
7. 最后一格打包本次结果。点击Save Version保存并等待完成，到保存版本的Output下载ZIP，避免临时会话丢失及下载404。

默认Run All不会冻结或运行评估集。脚本路径和标签文件名均在Notebook中明确。相同输出文件存在时脚本停止，避免把旧预测覆盖；重跑请创建新实验输出目录。

## 指标和结果如何解释

每类属性输出有效真值数、覆盖率、准确率、宏F1、逐类precision/recall/F1及支持量、混淆矩阵，以及错误案例CSV。缺失类别单独列出，零支持的recall不伪造为有效测量。宏F1默认对有真实支持的类别平均，另附固定词表缺失类按0的宏F1，避免混淆定义。

保留全部余弦分数和top-2差值、实际预处理、候选提示词、官方代码commit、权重哈希、Python/PyTorch/GPU信息、脚本和协议哈希。差值不是校准概率。本版没有选择拒识阈值，不凭空给出门控通过率；已计分真值的无拒识保留率为100%，需同时看有效标注覆盖率。

报告没有“达到80%即合格”的自动规则。得到真实结果后，结合逐类支持量、混淆、遮挡和错误类型，由团队明确哪些属性可用于反馈、哪些保持不确定、哪些暂时不启用。开发50/评估100样本量有限，缺失类别不能声称已验证；这也不是独立外部基准。单一主体图案评价不能替代多标签识别评价，三属性诊断不能代表全部25项映射的识别效果。
