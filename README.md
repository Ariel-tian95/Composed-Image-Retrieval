# 面向细粒度属性操作的零样本组合图像检索方法研究

> Zero-Shot Composed Image Retrieval with Fine-Grained Attribute Transition Feedback

## 1. 项目简介

本项目面向电商服装商品搜索场景，研究融合细粒度属性状态转移评价与视觉意图反馈机制的零样本组合图像检索方法，并实现一个可交互的服装商品检索原型系统。

传统图像检索主要根据用户上传图片的整体视觉特征寻找相似商品。当用户希望以一张商品图片为参考，同时通过自然语言描述修改其中部分属性时，传统图像检索难以准确理解用户的细粒度需求。

例如，用户上传一张红色长袖衬衫图片，并输入：

“Change the color to blue while keeping the long sleeves.”

系统需要同时理解：

- 参考图片提供的整体视觉信息；
- 用户希望修改的商品属性；
- 用户希望保留的商品属性；
- 修改后商品与参考商品之间应保持的视觉关联。

组合图像检索（Composed Image Retrieval，CIR）能够将参考图片和自然语言修改描述共同作为查询，从商品图库中检索符合用户需求的目标图片。

零样本组合图像检索（Zero-Shot Composed Image Retrieval，ZS-CIR）进一步要求模型不依赖目标检索任务的训练三元组完成组合检索，具有较好的跨任务迁移研究价值。

本项目以 **Context-I2W（AAAI 2024）** 作为主要学习与复现论文，在此基础上研究属性状态转移评价与视觉意图选择之间的反馈关系。

项目拟通过分析参考商品、修改指令和候选商品之间的属性变化关系，构建属性评价反馈信号，并尝试利用该信号调整模型的视觉意图选择机制（Intent View Selector，IVS），使模型能够根据当前查询的检索表现自适应调整视觉信息提取方式。

项目最终将实现一个服装零样本组合图像检索原型系统，通过基线对比、消融实验和属性一致性评价验证方法的可行性。

---

## 2. 项目目标

本项目主要完成以下五项任务：

1. **模型学习与基线复现**
   - 学习 CLIP、多模态特征对齐和组合图像检索的基本原理。
   - 理解 Context-I2W 的整体结构与核心机制。
   - 理解 Intent View Selector（IVS）和 Visual Target Extractor（VTE）的作用。
   - 使用 FashionIQ 数据集开展零样本组合图像检索基线实验。
   - 复现或验证 Context-I2W 在目标数据集上的检索表现。

2. **服装属性识别与结构化表达**
   - 调研 Fashionpedia、DeepFashion、VAW 等公开属性数据集。
   - 建立适用于服装检索的统一属性词表。
   - 识别参考商品与候选商品的颜色、袖长、服装类别、图案、版型等属性。
   - 从自然语言修改描述中提取属性操作要求。
   - 将属性信息转换为结构化表示，并保留预测置信度和不确定状态。

3. **属性状态转移评价**
   - 分析参考商品、修改指令和候选商品之间的属性关系。
   - 区分需要修改、需要保留和未明确指定的属性。
   - 判断候选商品是否符合用户提出的属性变化要求。
   - 构建属性状态转移一致性评价方法。
   - 分析属性评价结果与原始视觉检索结果之间的差异。

4. **反馈驱动的视觉意图自适应**
   - 研究如何将属性状态转移评价结果转化为反馈信号。
   - 探索利用反馈信号调整 Context-I2W 中 IVS 的方法。
   - 研究视觉检索分布与属性评价分布之间的关系。
   - 加入置信度门控、更新幅度限制和查询锚点等机制。
   - 通过实验验证反馈机制是否能够改善检索结果。

5. **原型系统开发**
   - 支持参考图片上传。
   - 支持自然语言修改需求输入。
   - 展示初始检索结果和反馈调整后的结果。
   - 展示候选商品的属性状态转移评价。
   - 支持检索结果及属性匹配情况对比。

## 3. 核心研究思路

### 3.1 主要复现论文

**Context-I2W（AAAI 2024）**

论文名称：

*Context-I2W: Mapping Images to Context-Dependent Words for Accurate Zero-Shot Composed Image Retrieval*

论文主要研究零样本组合图像检索中的上下文相关图像信息映射问题，通过视觉意图选择和视觉目标提取，将参考图片中的相关视觉信息映射为上下文相关的伪词表示，再与修改文本进行组合检索。

论文重点涉及：

- CLIP 视觉与文本特征空间；
- 上下文相关图像信息映射；
- Intent View Selector（IVS）；
- Visual Target Extractor（VTE）；
- 图像与文本特征组合；
- 零样本组合图像检索；
- Recall@K 等检索评价指标。

其中：

- **IVS**：根据组合检索任务动态选择参考图片的视觉意图或视觉视角。
- **VTE**：通过可学习的查询机制提取与当前检索任务相关的局部视觉目标信息。
- **Context-I2W**：将参考图片中的任务相关信息映射为上下文相关的伪词表示，以实现图像与文本的组合检索。

论文及代码：

- 论文：https://arxiv.org/abs/2309.16137
- AAAI 官方论文：https://ojs.aaai.org/index.php/AAAI/article/view/28324
- 官方代码：https://github.com/Pter61/context-i2w

复现原则：

优先使用官方代码和预训练权重完成模型加载、推理与基线评估，再根据实际算力条件开展必要的模型调整。

本项目不将完整重新训练 Context-I2W 作为硬性要求。实际完成情况将区分预训练模型推理、基线复现、模块调整和测试时自适应实验等不同层次，并在实验记录和论文中如实说明。

### 3.2 创新研究方向

本项目拟研究：

**属性状态转移反馈驱动的零样本组合图像检索方法。**

核心研究问题：

在零样本组合图像检索中，如何利用参考商品、自然语言修改指令和候选商品之间的细粒度属性状态转移关系，构造有效的反馈信号，并利用该信号调整视觉意图选择机制，从而改善模型对用户修改需求的理解和检索表现？

本项目拟采用以下研究流程。

#### 第一阶段：Context-I2W 初始检索

输入：

- 参考商品图片；
- 自然语言修改描述。

使用 Context-I2W 生成组合查询表示，从目标商品图库中检索候选商品。

得到初始检索结果及其视觉相似度分数。

#### 第二阶段：结构化属性状态提取

对参考商品、修改描述和候选商品进行属性分析。

重点关注：

- 服装类别；
- 颜色；
- 袖长；
- 领口；
- 图案；
- 版型；
- 材质或纹理等。

将属性信息转换为统一的结构化表示，并区分属性修改要求、属性保留要求和未明确指定的属性。

例如：

用户输入：

“Change the color to blue while keeping the long sleeves.”

结构化状态示例：

```python
query_constraints = {
    "modify": {
        "color": "blue"
    },
    "preserve": {
        "sleeve_length": "long"
    },
    "unspecified": [
        "fit",
        "pattern",
        "collar"
    ]
}
```

以上结构仅为示例，实际属性类别和输出格式以最终属性词表为准。

#### 第三阶段：属性状态转移评价

根据参考商品属性、用户修改要求和候选商品属性，判断候选商品是否符合预期的属性变化。

例如：

| 属性 | 参考商品 | 用户要求 | 候选商品要求 |
|---|---|---|---|
| 颜色 | 红色 | 修改为蓝色 | 蓝色 |
| 袖长 | 长袖 | 保留 | 长袖 |
| 服装类别 | 衬衫 | 未指定修改 | 尽量保持 |
| 图案 | 条纹 | 未指定修改 | 不作为强制条件 |

通过属性状态转移评价，得到候选商品对当前修改指令的符合程度。

需要注意，未指定修改的属性不能简单视为必须保持不变；属性识别结果不确定时，也不能直接作为可靠的反馈依据。

#### 第四阶段：属性评价反馈驱动 IVS 调整

本项目的重点不只是将属性得分加入检索结果排序，而是进一步研究：

**属性状态转移评价结果能否反向提供信息，帮助视觉意图选择机制调整当前查询中的视觉信息提取方式？**

拟研究以下过程：

1. 获取 Context-I2W 的初始视觉检索结果。
2. 计算候选商品的属性状态转移评价结果。
3. 比较视觉检索分布与属性评价分布。
4. 根据两者之间的差异构造反馈信号。
5. 将反馈信号用于 IVS 的有限测试时调整。
6. 重新生成组合查询并执行检索。
7. 比较调整前后的检索指标和属性一致性。

初步研究可采用视觉检索分布与属性评价分布之间的差异构造反馈目标。

例如：

$$
P_v(c)=\mathrm{Softmax}(S_v(c))
$$

$$
P_a(c)=\mathrm{Softmax}(S_a(c))
$$

$$
L_{\text{align}}=D(P_v,P_a)
$$

其中：

- $S_v(c)$：候选商品的视觉检索得分；
- $S_a(c)$：候选商品的属性状态转移评价得分；
- $P_v(c)$：视觉检索分布；
- $P_a(c)$：属性评价分布；
- $D$：用于衡量两种分布差异的函数。

以上仅为初步研究形式，具体反馈目标、可微优化方式和参数更新策略需要结合 Context-I2W 的代码结构进一步确定。

由于离散 Top-K 排名不能直接进行普通梯度反向传播，研究过程中需要考虑 Softmax 分布、Soft Ranking 或其他可微替代方案。

同时，为防止属性预测错误造成反馈累积，需要研究：

- 属性预测置信度门控；
- 原始查询锚点约束；
- IVS 参数更新幅度限制；
- 反馈更新次数限制；
- 多候选结果的一致性判断；
- 反馈效果不佳时的回退机制。

#### 第五阶段：实验验证

通过以下实验验证方法：

- Context-I2W 原始基线；
- Context-I2W + 属性状态转移评价；
- Context-I2W + 属性反馈驱动 IVS；
- 去除置信度门控的消融实验；
- 去除查询锚点约束的消融实验；
- 不同反馈更新次数的对比实验。

分析反馈机制是否能够改善 Recall@K、属性一致性和检索稳定性。

### 3.3 创新研究边界

本项目不将简单的属性识别、属性加权排序、候选结果重排序或多个视觉特征模块的拼接直接宣称为原创贡献。

正式创新点需要结合已有研究进一步查新，重点关注：

- 属性状态转移评价与视觉查询调整之间的关系；
- 属性评价结果能否构成有效的视觉意图反馈信号；
- 反馈信号如何作用于 IVS，而不只是改变候选商品的最终排序；
- 测试时反馈优化与传统相关性反馈、伪标签自训练之间的区别；
- 置信度门控和查询锚点如何降低错误反馈的累积风险。

重点参考 Context-I2W、DiffComp、SOP、ARTEMIS、CCIN 等相关工作。

如果发现核心反馈机制已经存在高度相似的研究，应重新评估方法的创新边界，而不是通过更换名称来包装创新。

另外，本项目以 FashionIQ 作为目标检索测试数据集，不使用其目标任务训练三元组训练核心检索模型。属性识别模型可以利用 Fashionpedia、DeepFashion、VAW 等外部公开标注数据训练。

如果测试过程中根据当前查询更新 IVS，应明确描述为零样本检索框架下的测试时自适应，而不是严格意义上的 Training-free。

- Shirt
- Toptee

Wu, H., et al. (2021). Fashion IQ: A New Dataset Towards Retrieving Images by Natural Language Feedback. CVPR 2021.

https://openaccess.thecvf.com/content/CVPR2021/html/Wu_Fashion_IQ_A_New_Dataset_Towards_Retrieving_Images_by_Natural_CVPR_2021_paper.html

- Context-I2W 基线检索；
- 零样本组合图像检索评估；
- 反馈机制对比实验；
- 消融实验；

## 6. 实验设计

### 6.1 基线实验

复现 Context-I2W，验证其在 FashionIQ 上的零样本组合图像检索能力。

主要指标：

- Recall@10
- Recall@50

记录不同类别的检索表现，并与公开论文或官方实现中的结果进行对照。

如果数据划分、模型权重或运行协议存在差异，应如实记录，不能直接将不同设置下的结果视为严格可比。

### 6.2 属性识别实验

对服装属性识别模块进行独立评估。

重点分析：

- 颜色识别准确率；
- 袖长识别准确率；
- 服装类别识别准确率；
- 图案识别准确率；
- 属性预测置信度；
- 不同属性之间的混淆情况。

通过人工检查和标注数据评价属性识别结果，为后续反馈机制提供可靠性依据。

### 6.3 属性状态转移评价实验

比较参考商品、修改描述和候选商品之间的属性关系。

重点评价：

- 修改属性符合率；
- 保留属性符合率；
- 属性状态转移一致性；
- 不确定属性的处理情况。

属性状态转移评价需要建立明确的标注规则和独立测试样本，不能直接由 Recall@K 推导。

### 6.4 反馈机制实验

比较以下实验方案：

| 实验组 | 方法 | 目的 |
|---|---|---|
| Baseline | Context-I2W | 建立原始检索基线 |
| Attribute Evaluation | Context-I2W + 属性状态转移评价 | 检验属性评价能力 |
| Feedback | Context-I2W + 属性反馈驱动 IVS | 检验反馈机制 |
| Feedback w/o Gate | 去掉置信度门控 | 验证置信度门控作用 |
| Feedback w/o Anchor | 去掉查询锚点约束 | 验证查询稳定性约束作用 |

重点分析反馈机制是否能够改善检索结果，而不是只比较属性评分是否提高。

### 6.5 消融实验

计划分别研究：

- 不使用属性状态转移反馈；
- 使用属性评价但不调整 IVS；
- 去掉置信度门控；
- 去掉查询锚点约束；
- 改变反馈更新次数；
- 改变候选集合大小；
- 改变反馈信号的构造方式。

消融实验用于判断每个模块是否真正产生作用，避免仅凭完整模型结果推断各个模块有效。

### 6.6 评价指标

| 指标 | 评价目的 |
|---|---|
| Recall@10 | 目标商品是否出现在前10个检索结果中 |
| Recall@50 | 目标商品是否出现在前50个检索结果中 |
| Precision | 预测结果中符合条件的比例 |
| Recall | 实际符合条件的样本中被正确识别的比例 |
| F1-score | 综合评价属性识别准确性 |
| Attribute Transition Consistency | 候选商品对属性变化要求的符合程度 |
| Query Latency | 单次查询检索耗时 |
| Feedback Latency | 反馈调整额外耗时 |

说明：

Recall@K 用于标准组合图像检索评估。

属性状态转移一致性需要独立制定评价标准，并通过人工标注或可靠的属性标签进行验证。

### 6.7 结果分析

实验结束后重点回答以下问题：

1. Context-I2W 是否能够正常复现？
2. 属性识别模型是否能够提供足够可靠的属性信息？
3. 属性状态转移评价是否能够反映用户修改需求？
4. 属性评价结果与视觉检索结果之间是否存在可利用的差异？
5. 反馈调整 IVS 后，Recall@K 是否得到改善？
6. 反馈机制是否提高了属性一致性？
7. 反馈是否会引入额外推理开销？
8. 哪些属性类型更容易发生错误反馈？

## 13. 项目当前需要重点验证的问题

项目正式进入反馈机制开发前，需要完成以下验证：

1. Context-I2W 官方代码能否在 Kaggle 环境正常运行；
2. FashionIQ 数据集能否按照官方代码要求加载；
3. Context-I2W 的预训练模型能否完成单条查询和批量检索；
4. Fashionpedia、DeepFashion 的属性标签能否映射到统一服装属性词表；
5. 属性识别模型能否提供足够可靠的属性信息；
6. 修改文本中的属性操作能否可靠提取；
7. 属性状态转移评价能否有效反映候选商品对修改要求的满足程度；
8. 属性评价结果与视觉检索分数之间的差异能否形成有效反馈信号；
9. 反馈信号能否作用于 IVS，而不是仅仅改变最终候选商品排序；
10. 测试时 IVS 更新是否会引起查询语义偏移；
11. 反馈调整是否能够改善 Recall@K 和属性一致性；
12. 反馈机制与已有相关性反馈、测试时自适应和伪标签方法之间的区别是否明确。

如果属性识别准确率不足，应优先解决属性预测可靠性问题。

如果反馈调整没有带来检索提升，应检查反馈信号、候选集合质量和 IVS 更新策略，并保留失败实验结果。

如果发现反馈机制与已有方法高度相似，应重新评估研究方案，不应为了保留原方案而强行宣称创新。

## 16. 项目协作约定
